# 社区锦标赛接入（2026-10-30）

**2026-10-31更新：** 赛事已扩展并接入参与奖、排名奖、宝箱和收件箱，以下“两场/无奖励”描述为首次接通记录；当前规则与验证见 [奖励系统](rewards.md)。

此前锦标赛不可玩的原因是两处未接通：社区 Plus 继承了返回 None 的 tournament_query，原合作列表又用官方 cloud.connected 阻止查询。即使账号已登录，原页面也拿不到赛事。另有“测试版本不支持锦标赛”的旧提示。

现继续使用仓库原有 CoopBrowserWindow、TournamentButton、TournamentEntryWindow、TournamentScoresWindow 和合作计分页。未新增锦标赛页面，也没有把官方云状态伪装为已连接。社区分支查询账号主服务，并在收到真实报名确认后启动原 CoopSession；网络失败会留在原报名框提示错误。

当前按UTC每天生成两个社区赛事：`Challenges:Runaround` 与 `Challenges:The Last Stand`，使用仓库已有 tournament 游戏预设，1–4名本地玩家参加。两个项目均无需额外商品解锁。原仓库 USE_ENTRY_FEES=False，保持免费报名，不扣点券。赛事、报名和成绩由PostgreSQL保存，日期换场后历史记录仍保留。

报名ID绑定到具体CoopSession；重新参赛使用新报名，重试同一次请求不会重复生成记录。练习模式不提交比赛成绩，不能误用此前正式参赛的记录。赛事倒计时与“更多成绩”继续走原页面所需的数据格式。

本地合作成绩来源是客户端上报（API明确标记 client_reported），不是权威对战服务器验证结果。服务端验证报名归属、赛事项目、时间、分数类型/范围及重复提交，每账号取最好成绩。它与已注册对战服的联赛结算分开存储，不自动发放币、点券、联赛积分、奖杯或宝箱；当前没有配置赛事奖品，所以原奖品栏显示空值。后续若需要正式反作弊及自动奖励，需要增加可信比赛执行/验证来源。

| 接口 | 用途 |
| --- | --- |
| POST /v1/tournaments/query | 当前或指定赛事、剩余时间、成绩列表，均需玩家登录 |
| POST /v1/tournaments/{id}/entries | 免费报名；请求UUID去重，已结束赛事拒绝 |
| POST /v1/tournaments/{id}/scores | 绑定报名ID的单次成绩；重复相同提交返回原收据，改分拒绝 |

验证：后端14项、本地兼容8项通过；含并发重复报名/提交、其他账号代交、错误项目、无效时间/类型、最好成绩、无额外奖励和新后端进程恢复报名。真实桌面引擎完成登录、赛事查询、报名、原生CoopSession及对应游戏类创建，并检查练习模式不上传。没有注入玩家，没有运行完整对局；手机页面点击和真实成绩仍待用户操作验证。

手动验证：保留数据覆盖安装 `artifacts/android/ballistica-community-tournament-test.apk`，强行停止后重开并登录。在“合作 → 锦标赛”选择赛事，点击原报名框“开始/游玩”；加入本地玩家完成一场，然后查看原计分页及“更多成绩”。返回后再试练习，确认练习成绩不覆盖榜单。无需进入服务器目录中的对战服。
