# 社区商店、档案升级与联赛（2026-10-30）

本轮按用户追加需求扩展原计划范围。账号主服务独立保存余额、商品权益、订单、全局档案名与联赛；Headless 只负责可信比赛结果上报。未接入官方支付、官方账号资产或官方榜单。

后续界面已按用户要求恢复仓库原版入口，原测试页面说明由 [原版界面恢复记录](stock-ui-restoration.md) 覆盖。后端购买记录接口仍保留。

## 商店与测试购买

沿用原有币（tokens）、点券（tickets）、金卡（gold_pass）以及角色、地图、小游戏、图标、扩展的原始商品 ID。79 个目录项目的权益由后端保存，客户端原有角色和游戏解锁检查读取这些权益。当前社区价格：角色100币、地图150币、小游戏200币、扩展250币、图标50点券；这些是社区测试价格。

`COMMUNITY_TEST_PURCHASES_ENABLED=1` 才允许免费购买币、点券和金卡。默认值为0，LAN 启动脚本明确打开它，关闭后这些请求返回403。界面和收据明确标记“测试订单”；没有发起支付平台请求。

币包按仓库原始数量为50/500/1200/2600，点券包接口为300/1000/5000/20000；金卡每次延长30天，有效期内商品和档案升级可免币/点券兑换，但仍记录订单与实际权益。普通商品默认按余额扣除，余额不足、已拥有、过期报价均会拒绝。重复点击同一请求只结算一次，复用请求ID更换内容返回冲突。

## 档案升级

原档案编辑页的升级入口可用：先同步已编辑档案，查询名称与报价，再支付100点券升级（金卡有效时0点券）。升级后服务端保存 global 标记及唯一名称。名称经 NFKC、去首尾空格及 casefold 规范化；不同账号不能抢占等价名称。竞争失败不会扣费，删除档案会释放名称；客户端不能通过普通保存伪造升级。

## 联赛与比赛奖励

奖杯按钮打开社区联赛，按UTC自然月分赛季，可查看历史榜单、本人排名、场次、胜场及积分。参与有效对局得10分，获胜额外20分；胜者获得10币/30点券，其余玩家3币/10点券。段位按本月积分为 Bronze（不足100）、Silver（100起）、Gold（300起）、Diamond（600起）。同分先比较胜场，再按稳定UID排序。等级显示为积分每100分一级，新赛季重置。

仅接受持独立服务器密钥的注册 Headless 上报；必须至少有两个不同社区账号，并具有该实例的有效入房投递记录。本地单机不会自报公共联赛。Headless 从原生认证身份和真实 GameResults 收集名次，待上传结果落盘，网络恢复后重试；实例ID+比赛ID去重，避免重复发奖。永久拒绝的结果另存诊断文件。

## 接口与迁移

迁移 `0003_progression.py` 增加钱包、商品权益、订单、全局名称、比赛记录和赛季数据。部署前执行 `alembic upgrade head`。

| 接口 | 用途 |
| --- | --- |
| GET /v1/economy | 当前账号权威余额、权益、档案和联赛摘要 |
| GET /v1/store | 商品目录、价格及测试购买开关 |
| POST /v1/store/purchase | 带报价和幂等ID的购买 |
| GET /v1/orders | 当前账号购买及升级收据 |
| GET /v1/profiles/availability | 升级名称检查与价格 |
| POST /v1/profiles/upgrade | 全局档案升级 |
| GET /v1/league | 当月或指定赛季排行榜 |
| POST /v1/servers/{id}/matches | 服务器凭据保护的比赛结算 |

## 检查与手机手动验证

真实 PostgreSQL/Redis/TCP 后端回归12项通过；原有本地策略8项通过。桌面引擎实跑登录、商品页模型、免费币包、扣币角色、点券、升级、金卡、订单、库存与联赛数据模型。Android 包通过构建、签名、原生导出、资源及关键源码一致性检查。此记录不代表手机布局、点击和真实对战已经验收。

手机安装、输入、点击、重启和截图由用户操作，代理不调用ADB。建议顺序：

1. 保留应用数据覆盖安装 `artifacts/android/ballistica-community-plus-full-test.apk`，强行停止后重开，登录已有账号。
2. 商店免费购买币包和点券包，核对顶部余额；购买一个角色，确认扣币及库存显示，再到档案编辑选择该角色。
3. 用一个新名字保存档案，再升级；应扣100点券、显示升级状态，重开应用后保留。
4. 购买金卡，确认到期时间；再兑换另一商品和升级另一档案，确认免币/点券且订单有记录。
5. 打开奖杯页，未参赛账号显示真实空榜状态。两个不同账号在注册服完成比赛后，刷新核对积分和奖励；单个账号不会生成联赛成绩。

当前测试API为 `http://10.60.0.11:18080`，仅用于显式HTTP开发模式。公开部署仍需HTTPS。广告、第三方支付、官方邮箱和官方宝箱奖励不在本轮实现范围。
