# 内网真机反馈修正（2026-10-30）

后续手机操作、输入、安装、重启、截图均由用户执行；代理仅在电脑侧修改代码、构建和检查服务日志。已移除此前测试资料中与应用无关的手机主屏截图，不再采集手机画面。

本轮交付中心是社区账号主服务与服务器目录。Headless 是独立联调辅助进程；账号主服务可在没有游戏服时独立提供注册、登录、会话和档案接口，目录为空也是有效结果。

## 已定位的实际缺陷与修正

| 真机反馈 | 代码/日志证据 | 本轮修正 |
| --- | --- | --- |
| 后台注册成功但菜单显示未登录 | `_accept()` 给账号变更观察者传 None；`accounts.primary` 始终为空 | 建立经后端认证的 CommunityAccount，发布真实账号变更；菜单使用社区昵称，避免官方云订阅 |
| 默认账号档案不能保存 | 本地兼容层拒绝所有 `__` 开头档案，包括引擎内置 `__account__` | 明确支持内置账号档案；本地保存无需登录；账号档案按 UID 缓存，并通过专用 API 同步 PostgreSQL |
| 档案页面提示连接官方云失败 | Inventory 默认先取官方云页面 | 社区版直接使用原生本地档案编辑页，不尝试官方库存页面 |
| 单机入口要求登录 | Coop 入口检查官方 primary | 社区本地入口不要求社区或官方登录；不伪造已购权益 |
| 网络诊断持续报云连接失败 | 原诊断仍调用官方时间/云消息/V1 事务 | 社区诊断检查真实 `/health/ready`、`/v1/servers` 与已登录账号 `/v1/me` |
| 加入后立即断开 | Headless 日志 `No token in clientinfo msg` | 已通过 V2 入房认证的连接不再强制要求旧官方 tk；未认证路径仍拒绝 |
| 退出后停在黑屏/无法离队 | 断线返回主菜单只看 can_communicate，错误可能已经清除此标志 | 同时判断遗留 ClientSessionNet；本地离队无需等待远端 ACK 即清理连接并返回主菜单 |
| 集会变成账号测试表单 | 主菜单集会入口被替换为 CommunityWindow | 恢复 GatherWindow；社区 REST 目录接到原公开列表，保留排序、过滤和 UDP Ping；登录/注册仅在账号页 |

新增 API：`PUT /v1/me/profiles/{name}`、`DELETE /v1/me/profiles/{name}`；`/v1/me` 和登录响应附带 player_profiles。迁移为 `0002_profiles.py`。玩家档案由服务端预投递给对战服，不信任客户端自报 UID。

## 本轮验证边界

- 后端/客户端调度测试 9 项通过，含账号档案持久化与主账号变更回归。
- 本地策略测试 8 项通过，含内置账号档案保存。
- Android 修复版已构建；安装、菜单布局、重启自动登录及黑屏/离队回归尚需用户手动确认。
- 真实电脑端引擎验证社区主账号已生效。尝试用 Headless 充当 UDP 客户端时，引擎明确返回 `Not available in headless mode`；没有绕过该限制，UDP 加入/离队修复不宣称已经通过电脑或手机端实测。
- 内网测试 API 为 `http://10.60.0.11:18080`，仅显式开发模式使用 HTTP；该地址经电脑现有内网路由可达，不是同一 Wi-Fi 子网直连证明。

## 用户手动验证顺序

1. 保留应用数据安装新 APK，再在 Android 应用信息中“强行停止”，重新打开（不要清除数据）。
2. 先不加入服务器：确认左上角账号按钮是独立账号页；登录已有账号后返回主菜单，核对账号昵称。
3. 编辑并保存档案；强行停止后重开，确认账号自动恢复、档案仍存在。
4. 退出账号，确认本地游戏和本地档案编辑仍可用；设置中的网络测试应显示“社区网络诊断”。
5. 最后再登录，在“集会 → 互联网/公开”查看目录和 Ping，再尝试加入/离开。若黑屏仍出现，停止反复重试，记录发生在哪一步和可见提示，由用户决定是否提供应用日志。
